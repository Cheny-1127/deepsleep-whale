# 个人邮箱直接收件

**Goal:** 通过邮箱地址、邮箱类型及客户端专用密码直接使用 IMAP 接收邮件，替换误做的飞书开放平台授权。
**Why planning is required:** 新增个人邮箱凭据存储和认证边界。
**Acceptance:** 界面可配置飞书或自定义 IMAP；仅 TLS 连接且验证证书；收件箱只读；密码不进入快照、日志或明文文件；暂停和退出使在途响应失效；独立测试与隔离 Electron 交互测试通过。真实邮箱需要用户在本机填写凭据后验证。

### Outcome 1: 加密配置与只读 IMAP 收件
- Work: 新增 IMAP 客户端适配器及 encrypted store，删除本任务刚加入的 CLI 邮箱适配器；每分钟检查最近 100 封，按账号、UIDVALIDITY 和 UID 去重。仅下载按需查看且大小受限的邮件正文。
- Risks/open questions: 企业管理员可能禁用 IMAP；邮箱密码通常须使用专用密码。TLS、认证及系统存储失败时明确报错，不降级明文或关闭证书验证。保留旧 mail.json 而不继续使用或自动登录旧应用。
- Verify: `node --test test/imap-mail.test.cjs`

### Outcome 2: 本机邮箱配置与收件界面
- Work: 将原授权二维码入口替换为邮箱地址、类型（飞书/自定义 IMAP）、客户端专用密码、服务器和端口。首次连接不提醒历史邮件，列表和正文保持文本展示；不把内容交给 AI 或放入桌宠广播。
- Verify: `npm run check` 和 `PLAYWRIGHT_MODULE=... npm run test:mail`，检查截图。

### Evidence gate
- 只读及 TLS：适配器调用测试与模拟 IMAP 会话协议记录。
- 加密及秘密边界：保存文件和快照断言、错误脱敏、系统存储不可用失败测试。
- 去重和竞态：轮询、重启、UIDVALIDITY 变化、暂停时在途请求测试。
- UI：隔离界面真实填写、收件、查看、暂停及桌宠 IPC 拒绝测试。
