# 工作报告配置

从小屋左栏打开“工作报告”。可以先手工录入，之后逐项补充来源和模板；未配置的来源不会访问。数据保存在应用数据目录的 `work-reports.json`，独立于 Obsidian 的 Markdown 文件。

配置按“数据来源 / 自动整理 / 归档 / 周报模板”分类，切换页签保留本次修改。底部固定显示 GitLab 已选仓库数、是否有未保存修改及“取消 / 确定并保存”。保存成功后关闭配置；校验失败会定位到对应页签并展开字段，保留本次输入。

## 1. 日常记录与日程联动

点击“新增工作”，填写标题、项目、日期、完成／阻塞／计划状态，可补充详情和依据。按日期查看、编辑、排除或删除记录。默认同步日程备忘中已完成的工作待办，个人事项和循环提醒不纳入；撤销待办完成后不再纳入报告，删除原待办保留已完成的工作事实。

每条来源记录都有稳定标识，重复采集不会重复新增；人工编辑、排除和删除不会被后续扫描恢复。撤销的日程在重新完成后可再次纳入，但明确删除的工作记录不会自动恢复。

日程备忘的“完成历史”可按完成日期查看完成时的内容，删除原任务后历史保留；点击工作记录上的“查看当日日报”可打开对应日期的每日工作，日期按实际完成时间而非截止日期计算。同步需同时开启工作报告模块及“自动归入日程备忘中已完成的工作待办”。重新处理会撤销当前日报来源的完成状态，但不会抹去日程完成历史；再次完成后，日报来源更新到新的完成日期；同一条待办按任务 ID 只展示一条最新完成记录，同日或跨日再次完成均更新原记录，历史数量按任务去重。同名但任务 ID 不同的记录不合并。旧版跨日期重复快照在读取时不重写文件，只展示最新写入的一条；更正完成日期后原日期不再展示旧副本。

## 2. 手动与自动采集

在“配置”中添加来源，选择工作日期后点“采集当天”验证结果；当天已有采集数据时显示“更新当天”。手动操作只核对所选日期（上海时间 00:00–23:59:59；今天截至当前时间），补充新记录、更新已有来源，保留人工修改、排除、删除及合并判断。来源失败时保留上次有效数据，采集状态显示本次核对日期。未来日期不能采集。

自动采集默认回溯 14 天、每 15 分钟执行；支持 1–90 天及 5–1440 分钟，与页面选中日期无关。应用启动、唤醒和定时执行时按开关处理；退出、关机期间不运行。补查历史某一天可直接选择对应日期采集；长时间离线后，可扩大自动采集回溯范围，再由自动采集补查。

- **GitLab**：在“报告配置 → 数据来源 → GitLab 仓库”填写 HTTPS 站点地址和个人访问 Token，点击“连接并读取分组”。自建实例可包含部署子路径，例如 `https://gitlab.example.com/gitlab`；GitLab.com 默认地址无需修改。Token 使用 [`read_api` 权限](https://docs.gitlab.com/security/tokens/access_token_scopes/)，跨多个项目组应使用自己的个人 Token。
- **Jenkins**：在项目 `.env` 设置下面三项，页面添加生产任务路径（例如 `prod/orders`）、GitLab 业务仓库完整路径、发布目标和发布人账号（多项用逗号分隔），并在 GitLab 中勾选对应仓库。仅采集 `prod`、指定账号直接触发、最终 `SUCCESS` 且实际部署阶段成功执行的发布；构建、定时或没有对应用户原因的触发不纳入。还须确认发布变更中包含符合当前 GitLab 作者筛选的普通业务提交；仅代合并、替他人发版的记录不纳入日报。多父提交或明确的 Merge branch / Merge commit 等合并提交不作为本人业务贡献。作者名 / 邮箱的精确匹配规则与 GitLab 提交采集一致。混合发布保留全部实际发布明细，日报仅汇总包含本人业务提交的 MR；本人直接提交独立按自身内容展示，不借用同批同事 MR 的标题。

```dotenv
WHALE_REPORT_JENKINS_URL=https://jenkins.example.com
WHALE_REPORT_JENKINS_USERNAME=your-user
WHALE_REPORT_JENKINS_TOKEN=your-api-token
```

Token 只需指定任务历史的读取权限，仅主进程读取，不展示在页面或写入工作账本；`.env` 已忽略提交，建议权限 `600`。同名进程环境变量优先，修改后重启应用。请求仅使用历史 GET 接口，不触发构建或审批。

Jenkins 自动核验当前流水线的 `Deploy to EKS` 或 `发布/回滚/启动/停止` 阶段；旧流水线同时核对 `ACTION`，不再依赖“成功即发布完成”的手工勾选。以**部署阶段完成时间（上海时区）**筛选时间窗口、归入日报；构建开始、构建结束、代码提交和 MR 合并时间不能代替部署完成时间。今天发布昨天合并的代码，记录在今天。发布人指 Jenkins 直接触发账号，审批人不自动视为触发人。

按已选业务仓库路径识别发布 SHA，排除共享库和流水线脚本仓库。对同一任务、相同实际发布目标，取时间上前次成功部署（包含其他发布人的部署），比较前次 SHA 到本次 SHA，再关联已合并 MR 并读取 MR 提交说明（标题与正文）和作者；同时保存 MR 链接、版本与发布时间。直接提交单列；同版本重复部署因无新增本人提交不纳入；回退展示本次移除的 MR / 提交；分叉或已有制品无法确认实际 SHA 时提示人工核对，不猜测范围。没有前次成功发布时，仅核对目标版本关联 MR；无 MR 时读取目标提交的作者与说明，并在来源和明细注明完整范围待核对。MR 压缩合并会读取实际纳入的原始业务提交核对作者，普通合并及部分范围仅以发布差集中的本人业务提交作为归属证据，不用基线里已有的历史提交凑归属。晚于实际部署完成时间才合并的 MR 不关联到该次发布。重新采集成功后，当前来源及回溯窗口内已不符合规则的旧发布会停用；读取失败保留旧数据，人工编辑、排除和删除状态不被覆盖。

每个来源最多读取 201 次构建检测历史截断，部署阶段查询最多 201 次、GitLab 查询最多 400 次，单次版本比较、MR 或 MR 提交最多 200 条；内容过长或分页不完整不会截断保存。读取失败保留已有记录；成功核对后，本次时间窗口内不再符合发布证据的旧构建记录停止纳入报告，人工正文、排除和删除仍保留。接口依据：[Jenkins Remote API](https://www.jenkins.io/doc/book/using/remote-access-api/)、[Pipeline 阶段 API](https://github.com/jenkinsci/pipeline-stage-view-plugin/tree/master/rest-api)、[GitLab 版本比较](https://docs.gitlab.com/api/repositories/#compare-branches-tags-or-commits)与[提交关联 MR](https://docs.gitlab.com/api/commits/#list-merge-requests-associated-with-a-commit)。

每个来源独立展示最近结果。来源失败、未配置、筛选遗漏或超出回溯窗口时，报告可能不完整；生成前核对来源结果和记录，不把“暂无记录”当作该期间没有工作。该功能不会写入团队正式发布记录。

### GitLab 项目组与勾选

1. 首次连接会读取账号与项目组，确认读取权限后才保存连接。“提交作者筛选”可选择作者邮箱（email）或作者名（username / 姓名）。邮箱默认从账号带出；作者名可填写多个历史别名，例如 `yuchaoyuan, 余朝元`。多个值用逗号或换行分隔，去除首尾空格、不区分大小写，按完整值匹配；作者名模式不受历史提交邮箱误填影响。它匹配提交内的 author_name，不自动推断 GitLab 登录账号的归属。
2. 连接后直接以“项目组 → 子组 → 仓库”树形列出，重新打开配置会自动读取已保存连接。分组和仓库分页自动读完，支持逐项勾选或整组勾选（包含子组），部分选中时组复选框显示半选。可搜索名称或路径、全部展开或收起，筛选不清空已有勾选；刷新失败保留上次完整列表。
3. 最多选 200 个项目，点击底部固定的“确定并保存”后生效。取消配置不会保存本次勾选。连接验证属于独立操作，即使取消项目勾选，已验证的连接仍保留。
4. 点击“采集当天”或“更新当天”后，核对所选日期已选项目的远端提交，不需要克隆或拉取仓库。按所选方式精确匹配普通业务提交的作者名或邮箱，排除仅代合并的提交，按提交时间归入上海日期，重复采集以“实例地址 + 项目 ID + 提交 SHA”去重。为确认当天合并的 MR，可只读核对已记录的历史功能提交，但不改写其他日期的来源记录。单项目返回超过 2000 条提交会提示缩小范围，不保存该项目的半份结果。

切换筛选方式会保留另一种方式已填写的值，只有当前方式参与采集和必填校验。旧配置升级后仍使用邮箱模式；新方式与别名点击“确定并保存”后生效，重启保留。修改筛选不会自动删除已有工作记录，需要补采历史时先调整“自动整理”的回溯天数（最多 90 天）。

Token 使用系统安全存储加密后写入本机 `report-gitlab.enc`，不会返回页面或写入 `work-reports.json`；系统加密不可用时拒绝保存，不降级为明文。重新打开配置将连接信息收为一行，连接设置和作者筛选可展开修改，已选清单默认收起；Token 输入框显示“已保存 Token”，输入框留空点击“刷新项目”会复用该实例的已保存 Token；填写新 Token 可更新凭据，认证或读取项目组权限验证失败会保留旧连接。改变实例地址（包括部署子路径）时需填写对应的新 Token，再重新勾选并保存来源；不会将旧 Token 转发到新地址，已采集的工作记录保留。

GitLab 采集记录的是已提交的代码，不会把日程中待处理或处理中的任务自动标为完成。代码来源统一通过 GitLab 选择远端仓库，尚未推送的本地提交不会进入采集。接口依据：[项目组与组内项目](https://docs.gitlab.com/api/groups/)、[远端提交与分页](https://docs.gitlab.com/api/commits/)。

## 3. Obsidian 归档

在配置中填写或选择**已存在**的报告目录，默认子目录是“日报”和“周报”。也可在首次使用前设置：

```dotenv
WHALE_REPORT_OBSIDIAN_DIR="/workspace/note/Dd work report"
```

这个路径必须在运行桌宠的电脑上可访问。应用不会创建不存在的根目录；第一次保存页面配置后，以页面保存的目录为准，之后在页面修改。其他来源和周报格式都可以稍后补充。

日报默认以排版后的标题、加粗及分层列表预览，可切换“Markdown 源码”查看原文，归档仍保存原始 Markdown。日报预览后可归档；周报先生成或保存草稿，再归档。文件分别为 `日报/YYYY-MM-DD.md` 和 `周报/周一日期.md`。自动归档默认关闭，开启后处理变更过的日报（每轮最多 30 天）；同时开启自动周报时，也归档上一完整周的周报。

每个文件有一对 `<!-- deepsleep:… -->` 标记，应用只更新标记之间的内容，保留两侧手写备注。若你在 Obsidian 修改了标记内的内容，应用拒绝覆盖；请先保存修改到其他位置，再核对并恢复原托管内容，或在页面选择新的归档子目录。同名非本应用文件、链接文件及链接子目录也不会覆盖。不要删除标记来解决冲突。

## 4. 工作事项与报告格式

每日工作和日报按“日期 + GitLab MR 完整地址”汇总，同一 MR 的普通提交、合并事件与多个生产发布目标展示为一项代码工作；每个目标保留实际部署完成时间，按上海时间排序。采集提交时分页读取其关联的打开中或已合并 MR，仅接受同一项目的关联，并保存源分支、目标分支和合并时间。未创建 MR 时，只有提交唯一归属 `feat`、`feature` 或 `hotfix` 功能分支且不在 main/master 中，才按该分支汇总；之后可通过同仓库、同源分支的唯一 MR 接续关联。分支或 MR 存在歧义时保持独立，不按标题相似猜测。合并进度仅从本人普通业务提交已关联的 MR 生成，单纯替同事合并不会新增其工作事项。已核实的精确 MR 提交 SHA 可补充关联，正文里的 MR 引用不能代替本人业务提交。重新采集成功后，同一来源及回溯窗口内的旧代合并提交，以及缺少本人普通业务提交依据的旧合并事件会停用；失败保留旧数据和人工操作。

主列表统一展示“今日工作”，以事项说明做了什么、取得什么结果。代码功能的完成规则是：真实 Jenkins 生产部署已核实包含该事项关联的 MR 或同仓库功能分支提交，就显示“已完成”，不再用 MR 目标分支或合并状态阻止完成。尚未发布时，分支开发或打开中的 MR 显示“开发中”；合并发布分支后显示“待发布”，其中 `ossv/d-minitv-admin` 采用实际目标分支，其他项目按 `main` 判断待发布进度；合并信息缺失显示“待核对”。测试发布、构建成功但未部署、回退或未核实的变更范围不能作为功能完成证据。卡片保留最早的相关生产发布时间；手工完成的记录仍可独立显示“已完成”，实际阻塞和计划仍单独展示。列表统计工作事项数，发布事件数保留在来源数据中。

功能可跨多天、跨周推进，每天只展示当天实际提交、发布分支合并或生产发布产生的进展。合并单独记为事件并保留实际目标分支，即使当天没有新提交也能出现“待发布”。状态按所选日期截止计算，后续上线不会把之前的开发日报改成“已完成”，也不会提前完成上一周的工作。仍未完成的已有关联功能，每次采集会选取一个原有提交刷新 MR 信息，最多跟踪 200 项，继续遵循当前仓库和作者筛选；即使原提交已超出回溯窗口也能跟进后续合并，不额外导入其他人的提交。用户明确合并为同一业务事项后，其中关联代码已有生产发布即可将该事项记为完成，不要求前后端或每个发布目标分别完成；独立事项不会仅凭分支同名共用发布记录。

自动整理以 MR 标题、提交说明中已有的业务内容为依据，去掉 `fix(scope):` 等提交前缀，补充同一 MR 的简短变更说明；不将多个 MR 的正文混用，不编造来源没有说明的收益。同一事项的多个发布目标仍保留为一项工作。卡片标题右侧显示状态，标题下直接展示所属项目、MR 编号、各类来源数量和发布摘要；没有工作说明时可补充处理结果。SHA、分支名、完整提交正文、发布明细、来源范围提醒及来源记录的编辑/纳入/排除/移除操作保留在默认折叠的“来源记录”里，原始账本不因汇总被删除。采集状态默认收起，注明它统计的是整个配置回溯窗口，来源读取条数不是所选日期的工作数。

打开某天日报时，若该日旧 GitLab 记录缺少 MR 关联，或虽已关联但缺少状态、目标分支和合并时间，会自动核对已选仓库及当前作者筛选，给已有来源补充关联元数据；不添加新工作，不覆盖正文、日期、人工编辑、排除或删除状态。每天最多自动处理 200 条旧记录，同一天并发打开合用一次请求；所有待处理来源核对成功才保存，失败保留旧数据并集中提供“重试关联”。关联已核对的日期再次打开或应用重启后不重复核对，不要求逐条点击重新采集；远端仍未提供必要信息时保留“待核对”，后续常规采集可继续更新。手工调整日期、作者筛选变化或仓库不再选中导致历史来源查不到时，会明确提示核对配置。该流程不触发 Jenkins 采集或报告归档，也不改变自动采集开关。新采集和历史核对的单项目提交与 MR 查询合计最多 400 次，超限或关联读取失败时保留原有记录。

日程和手工记录默认独立，不要求有代码提交或发布。若计划完成记录与采集结果是同一件工作，点击列表上方的“合并同一事项”，按业务标题选择当天的两项工作，再选择采用哪条事项的标题和说明，也可自行修改；包含日程完成记录时默认采用日程内容。确认后每日工作、日报和重新生成的周报只统计一项，原始来源完整保留在折叠详情中。已有合并事项可继续从上方入口与其他工作合并，也可“修改信息”或“解除合并”恢复各自的工作。

误点“解除合并”后，原始来源仍保留。可以重新点击顶部“合并同一事项”，先合并两项，再与第三项合并；也可点击“重新检查已忽略的关联”，展开恢复的提示组并“确认合并”，一次恢复整组关联。

每张卡片的标题旁都提供铅笔图标，点击“修改信息”可编辑工作。手工记录、独立日程等单条事项可编辑原记录的标题、项目、日期、状态和说明；MR 自动汇总及已合并事项可修改报告中的标题和工作说明，保留原始来源，后续采集同一 MR 的提交仍归入原事项。单事项的人工整理可通过“还原修改”恢复来源中的标题与说明；这与解除多项工作的合并分别保存，重启后仍可使用。

工作卡底部可直接点击“移除”，确认后一次移除这项工作当前包含的来源记录，不必逐条展开。移除的记录不进入后续生成的报告，重启或重新采集也不会恢复这些记录；此操作仅针对当前记录。同一来源同时用于其他工作时，整项移除按钮不可用，需先在来源记录中核对。已保存的日报、周报不会自动改写。

合并关系按日期保存，重启及重新采集后仍有效；同一天、同一 MR 后续采集到的新提交也归入原事项，不凭标题相似自动合并。仅允许合并当天已有的完成／代码进展记录，不会把待处理、处理中、计划或阻塞事项自动标为完成。排除、删除或撤销的来源不会因合并恢复，所有来源都不再纳入时不显示该合并事项。若后续 MR 核对造成来源对应多个合并事项，会保留工作并在来源详情提示解除冲突关系。已保存的手工周报草稿不被改写，需确认后重新生成；已归档日报需重新归档才更新。

每日工作会自动检查当天的疑似重复事项；页面打开期间，采集或日程完成后的来源变化会自动刷新提醒。相同 MR 仍直接汇总；不同事项若具有相同功能分支，或 `feat-cy-日期-描述` / `hotfix-cy-日期-描述` 去掉类型、作者和日期后描述相同，会优先在列表上方提示“可能是同一件工作”，说明相同分支或任务描述，等待确认后合并。完全相同的有效业务标题或说明也作为优先线索，忽略提交类型前缀、大小写、空白及末尾句号；通用说明和“代码已合并 main”这类系统文案不作为任务描述。仍会检查标题、备注中多个具体内容线索的重合。共享同一事项的候选会聚成一组，例如两个仓库的 MR 都关联到同一条日程时，组内展示三项，日程只展示一次；已忽略的关系不会通过其他事项间接归入同一组。每组使用同一个外框，默认收起，仅显示业务主标题、“待确认关联”标记及带底色的内容线索。点击主标题后展开组内各项等宽卡片，每行两张，展示各自的标题、说明及可展开的来源记录，窄窗口上下排列；确认操作放在展开区底部，组内事项不再重复列在普通工作列表中。自动刷新保留当前展开状态。组标题旁提供编辑图标，无需展开对比即可修改并保存该组标题，取消或按 Escape 放弃修改。标题独立保存，不修改组内各项或执行合并，刷新、重新采集及重启后保留。点击“确认合并”直接保存整组关系，使用已保存的组标题；未修改时优先采用日程完成记录的标题和说明，之后仍可编辑或解除；点击“不是同一件”会保存整组判断，重启及同一 MR 后续新增提交不再重复提醒。当天已忽略的关联可点击“重新检查已忽略的关联”恢复检查。解除合并后也会忽略恢复出来的当前疑似关联，避免立即再次催促合并。

此版本使用本地内容规则，不调用外部模型，不产生模型费用或外传工作内容；它不具备完整语义理解，不保证发现所有重复，也不把内容相近直接当作同一事项。不同日期、未完成/阻塞、已排除/删除/撤销的来源不作模糊匹配；已知不同项目只有在相同功能分支、相同有效任务描述时可直接产生待确认提示，其他内容线索仍需通过共同日程进入同一待确认组。日期和项目本身不构成重复证据。每次最多检查最近 500 项有效工作，每项使用标题及前 1600 字说明、最多 80 个线索词，候选比较有数量限制，最多显示 20 组提醒，每组最多 50 项；达到检查、展示或组内项数上限时会明确提示可能有遗漏，仍可使用手工合并。

疑似关联的共同内容线索放在每组外框顶部，使用较小字号及浅色底。日程备忘在事项上显示为“日程备忘 · 名称”标签；GitLab/Git 提交、发布及手工记录在来源抽屉中也只显示简短名称，不内嵌整张原始记录卡。鼠标悬停或键盘聚焦名称后显示日期、完整内容、链接及编辑/排除/移除操作，按 Escape 可关闭。来源记录条数只统计该抽屉内的其他记录，原始账本和日报汇总不变。

旧版明确选择的 MR 关联继续保留，可从卡片解除。对应 MR 不在当天纳入记录里时，补充记录独立展示，关联提醒保留在来源详情。人工编辑过的提交或发布保留独立展示，避免汇总覆盖整理内容；单纯纳入/排除不视为正文编辑。重复发布和回退记录不冒充新增功能；发布范围核对信息仅影响来源追溯，不把已成功发布的事项标成待解决。

日报预览、归档和周报正文使用同一事项描述，不列 MR、分支、构建编号和发布流水。周报按上海时间周一至周日统计；同一功能跨天只汇总和计数一次，按该周截止时的状态展示，按天明细仍保留每天的进展。显式合并的事项沿用人工标题与说明，独立日程和手工事项不会仅凭标题自动跨天合并。默认模板包含本周工作、问题与风险、下周计划，旧版未修改的默认模板自动采用新格式，自定义模板和已手工保存的周报草稿保留。`releases` 占位符列出已发布的工作事项，`details` 列出按日期整理的事项内容；技术证据仍在应用来源详情中追溯。生成不使用模型，不编造成果。

在配置中编辑模板，可使用以下占位符：

| 占位符 | 内容 |
| --- | --- |
| `{{week_start}}` / `{{week_end}}` | 本周一／周日日期 |
| `{{summary}}` | 本周工作事项、进展及结果 |
| `{{releases}}` | 已成功发布的工作事项 |
| `{{blockers}}` | 本周阻塞事项 |
| `{{next_week}}` | 下一周日期范围内的计划事项 |
| `{{details}}` | 本周按日期整理的工作事项 |
| `{{count}}` | 本周汇总后的工作事项数 |

周报页面选择该周任意一天，生成后可人工编辑并保存草稿。自动生成默认关闭，开启后定时整理**上一完整周**；手动编辑过的草稿不会被自动重生成覆盖。手动重新生成需确认。更早周报的补录、修改，需选择对应周重新生成和归档。

关闭工作报告模块后暂停采集、联动和归档，保留数据；重新开启后恢复。归档失败或磁盘保存失败时保留原记录并显示错误。迁移前退出应用，备份 `work-reports.json`、报告目录及 `.env`。
