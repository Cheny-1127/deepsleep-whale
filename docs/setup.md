# 安装与功能配置指南

本文面向在自己 Mac 上运行 deepsleep-whale 的使用者，说明各功能需要准备什么、在哪里配置，以及怎样确认接入成功。功能细节和开发验证命令见 [README](../README.md)。

部署范围为 macOS，采用源码加 Node.js／Electron 运行。本文不包含打包安装器、开机自启或跨系统部署步骤。

### 开发验证与日常实例隔离

UI 调试和自动化测试默认使用独立数据目录并隐藏窗口。确有需要时，可以显示独立测试窗口；验证焦点、原生菜单或前台交互时，允许测试实例抢焦点。优先用程序直接驱动测试界面，仅观察时可选择显示但不抢焦点。

这项许可只针对测试实例，不代表可以操作用户日常运行的 DeepSleep、使用真实数据目录测试，或修改正式窗口行为、启动选项、账号及功能配置。正式实例的重启、配置修改或真实数据验证，需要用户针对该操作的明确要求。测试结束仅清理测试实例及其资源。

Agent 执行细则见项目根目录 `AGENTS.md`；该文件已随仓库管理，新电脑或新副本也应遵循本节约定。现有 `WHALE_TEST_WINDOWS=inactive` 是“显示但不抢焦点”，不能将它理解为前台聚焦模式。

## 1. 安装与启动

准备 macOS、Node.js 22 或更新版本及 npm。在终端进入取得的 `deepsleep-whale` 项目目录后执行：

```sh
node --version
npm ci
npm start
```

本项目将 Electron 放在开发依赖中，源码运行时也需要安装开发依赖；不要使用 `--omit=dev`，设置了 `NODE_ENV=production` 的终端应显式运行 `npm ci --include=dev`。

首次启动默认显示控制小屋和桌宠。后续也可以在 Finder 中双击项目根目录的 `start.command`。关闭小屋后应用仍在运行，从菜单栏可以重新打开小屋或退出。

桌宠互动、快捷操作和日程备忘可以独立使用。需要其他功能时，按下面的表格配置；无需一次配置全部服务。除陪伴小屋外，各模块右上角都有总开关，开启后还需完成该模块的账号或来源配置。

### 新电脑部署前核对

先决定这台 Mac 要启用哪些模块，再准备对应依赖。表中的个人路径、登录和凭据均按目标电脑配置，不应直接照搬开发电脑的值。

| 项目 | 当前是否可配置 | 新电脑上的处理方式 |
| --- | --- | --- |
| 项目位置与 Node 路径 | 按本机安装位置生成 Hooks 命令 | 在目标 Mac 安装 Node、执行 `npm ci`，再安装该机器的 Hooks；不要复制旧机器的 Hook 绝对路径 |
| Codex 程序路径 | 自动检测，或设置 `WHALE_CODEX_BIN`；微信实例也可单独指定 | 先在本机确认客户端可用；不在默认位置时配置真实可执行文件路径 |
| Codex 配置目录 | `CODEX_HOME`；微信实例可单独指定 | 使用本机实际目录，完成本机客户端登录；Hooks、Archery 和实例配置分别核对 |
| Cursor 与项目目录 | Hooks 目录和状态库可通过环境变量指定；微信客户端和项目在界面选择 | 安装所需客户端，重新选择本机存在的项目与对话；Cursor 微信任务还需要 CLI 登录 |
| Sub2API 目标地址 | 项目根目录 `.env` 的 `WHALE_QUOTA_BASE_URL`，或同名进程环境变量 | 按目标站点填写地址，无需修改代码；目标服务须支持对应管理接口，详见第 7 节 |
| Sub2API 管理 Key | `.env` 的 `WHALE_QUOTA_API_KEY`；兼容旧 `token` 文件或 `WHALE_QUOTA_TOKEN_FILE` | 在目标 Mac 私下填写管理 Key；`.env` 和 `token` 均被 Git 忽略，复制源码不会带上凭据 |
| Archery | 读取本机全局 MCP 配置和账号变量 | 单独安装适配的 MCP，替换程序路径，配置服务地址、账号和工具权限；安装桌宠不会自动安装它 |
| 微信、邮箱 | 扫码或界面填写，使用系统安全存储保存 | 在目标 Mac 重新扫码或填写邮箱授权码；旧机器的加密文件不保证能直接使用 |
| 通知、数据目录与网络 | 通知按本机授权，数据默认位于当前用户目录 | 在本机确认通知及外部服务可达；自定义数据目录时保持 Hooks 与桌宠一致 |
| 启动环境 | 额度及工作报告配置自动读取项目根目录 `.env`；其他个人变量仍由启动进程提供 | 终端和双击启动均读取这些配置；依赖其他环境变量的模块仍需按日常启动方式分别验收 |

**配置范围：** 项目 `.env` 当前只读取额度及工作报告相关变量，不统一加载其他模块的环境配置。Archery 的 MCP `.env` 仍不足以单独完成桌宠接入，需按第 6 节配置全局 MCP 和账号。

新电脑建议按下面顺序验收：

1. 取得项目源码后，在目标 Mac 的项目目录执行 `npm ci`、`npm start`，确认小屋和桌宠正常显示。不要依赖从其他机器复制来的 `node_modules`。
2. 关闭本机不使用的模块，确认要启用模块的前置服务、客户端、账号及权限已准备好。
3. 按上表替换机器相关路径与配置。启用额度前，将 `.env.example` 复制为 `.env`，先确认目标 Sub2API 地址，再填写该站的管理 Key。
4. 在目标电脑安装、启用并按需信任 Hooks；微信扫码、邮箱配置和 Archery 连接在本机分别完成。按第 2 节执行各模块最小验收。
5. 正常退出后，以预计日常使用的方式重新启动，再确认配置保留、客户端能找到、已启用功能可用。终端启动成功不等于双击启动也成功。

有旧数据迁移需求时，先看第 9 节，特别是系统加密文件与绝对路径的限制。安装完成不代表所有可选模块均已接入，交付时应记录本机实际启用及验收通过的功能。

| 功能 | 必须准备 | 配置入口 | 最小验收 |
| --- | --- | --- | --- |
| 桌宠互动、快捷操作 | 本地运行环境 | 陪伴小屋、快捷操作 | 喂饭或摸头动作正常，快捷操作保存后生效 |
| 日程备忘 | 本地运行环境；系统通知按需授权 | 日程备忘 → 默认配置、新建事项 | 在允许时段内到期，桌宠出现提醒 |
| Codex 提醒 | 支持 Hooks 的本机 Codex、已安装且已信任的提醒 Hooks | Hooks 配置、Codex 的 Hooks 管理入口 | 真实聊天完成一次工具调用和回复后收到新事件 |
| Cursor 提醒 | 支持对应 Hooks 的本机 Cursor | Hooks 配置 → Cursor 总开关 | 真实 Cursor 任务触发事件，最近接收时间更新 |
| 微信远程任务 | 微信扫码、本机已配置并可用的 Codex 或 Cursor CLI、联系人授权 | 微信接入 → 扫码连接、微信设置 | 先确认连接，再选择项目或对话，发问题并收到回复 |
| 邮箱接收 | 已开启 IMAP 的邮箱、客户端专用密码或授权码 | 邮箱接收 | 最近邮件列表成功更新，能打开一封邮件 |
| Archery 待我审核 | 本项目适配的 Archery MCP、全局 MCP 配置、服务端账号及权限 | Codex 全局配置、Archery 页面 | 待我审核列表刷新成功；无待办也可以是正常结果 |
| 上游账号额度、消费排行 | Sub2API 管理 Key、匹配的服务地址和管理接口 | 项目 `.env`、API 额度 | 手动刷新成功，账号或排行数据按权限与实际数据展示 |
| 桌宠流量跟踪条 | 已成功同步的上游账号额度、选定的跟踪账号及有效的 7 天额度 | API 额度 → 流量跟踪配置 | 桌宠额度条显示所选账号的 7 天剩余比例 |
| X 消息订阅 | 可访问 X 公开页面的网络、订阅账号 | 消息订阅 → 订阅管理 | 添加账号后立即检查，取得页面可见动态 |
| 动态中文翻译 | 可访问 Google 翻译接口的网络 | 动态卡片 → 中文翻译 | 点击后出现译文 |

### 前置功能与配置顺序

`npm ci` 只安装桌宠自身依赖，不会安装 Archery 服务、Archery MCP、Sub2API 或执行任务的客户端。下表中的前置服务与账号需要先准备好，再配置对应功能。

| 要使用的功能 | 前置依赖顺序 | 未完成时的影响 |
| --- | --- | --- |
| Codex／Cursor 提醒 | 对应客户端已安装且支持所需 Hooks → 安装或补齐 Hooks → 按客户端要求启用、信任 → 开启桌宠来源接收 | 桌宠可运行，但收不到对应客户端的真实事件 |
| 微信远程任务 | 本机执行客户端已安装、登录且能完成任务 → 微信扫码 → 联系人授权 → 选择客户端、项目或对话 | 扫码只完成消息连接，执行客户端不可用时仍无法执行任务 |
| 微信任务中使用 MCP 工具 | 所选执行客户端已配置相应 MCP → 工具账号与权限可用 → 再从微信发起任务 | 微信连接和模型可用，也不代表所需工具已经可用 |
| Archery 待我审核 | 可访问的 Archery 服务及账号 → 安装适配的 Archery MCP → 全局配置注册启动入口和账号 → 开放列表工具 → 再开启桌宠模块 | 仅开启页面无法读取工单；查看列表与审批还受不同权限约束，详见第 6 节 |
| 上游账号额度、消费排行 | 已运行的 Sub2API 服务及所需管理接口 → 确认目标地址 → 在 `.env` 配置管理 Key → 再刷新对应区块 | 只有凭据或只有桌宠，均无法取得服务端数据 |
| 桌宠流量跟踪条 | 上游账号额度同步成功 → 账号存在有效 7 天额度 → 选择跟踪账号 | 未选择账号或缺少有效数据时，额度条保持中性状态 |
| 邮箱接收 | 服务商开启 IMAP → 取得客户端密码或授权码 → 填写邮箱连接配置 | 仅有网页登录密码或邮箱地址，可能无法通过客户端认证 |
| 动态中文翻译 | 先取得动态正文 → 点击翻译 → 翻译服务网络可达 | 无正文无法翻译；订阅读取成功也不代表翻译服务可访问 |

按需完成相关依赖即可。桌宠的 Archery 页面会直接连接 MCP；微信任务访问工具时则沿用所选执行客户端的工具配置，两者应分别验收。

## 3. Codex 与 Cursor 提醒

### Codex

在项目目录预览配置，核对后安装：

```sh
node scripts/hooks/install.cjs
node scripts/hooks/install.cjs --install
```

默认写入 `~/.codex/hooks.json`；自定义 `CODEX_HOME` 时写入对应目录，必须与目标 Codex 使用的目录一致。安装器会保留已有 Hooks，覆盖前创建备份，不替用户修改信任设置。

安装后，在 Codex 桌面设置的 Hooks 页面，或交互式 CLI 的 `/hooks` 中，审核并信任命令指向本项目 `scripts/codex-hook.cjs` 的定义。新增或变更的定义需要重新审核；具体入口以所用客户端版本为准。信任要求见 [OpenAI 官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks)。

打开小屋的“Hooks 配置”，确认 Codex 来源开启并重新检测。保持桌宠运行，在真实 Codex 聊天中让它执行一次 `pwd` 并结束回复，检查最近接收时间及状态变化。“提醒桥已就绪”和手动播放动画只能证明本地功能可用，不能证明真实 Hooks 已接入。

### Cursor

打开“Hooks 配置”，主动开启 Cursor 总开关。应用会创建或补齐当前项目的五项 Hooks，保留其他配置并在修改前备份。默认目标为 `~/.cursor/hooks.json`；仅重新检测不会写入配置。

保持 Cursor 和桌宠运行，执行一次真实任务，确认 Cursor 来源的最近接收时间更新。逐项事件开关只控制桌宠是否接收，不删除客户端配置。

### 通知与路径

需要横幅时，开启小屋通知开关，并检查 macOS 的通知权限和专注模式；提示音默认关闭。日程的通知、声音在日程默认配置中单独设置。

Hooks 使用 Node 和项目的绝对路径。移动项目、更换 Node 路径或切换客户端配置目录后，需要更新接入配置，Codex 中有变化的定义须重新审核，再用真实任务验收。详细排查见 [README 的 Codex 接入说明](../README.md#codex-本地事件接入)。

## 4. 微信远程任务

**前置条件：** 本机执行客户端的安装、登录和模型服务配置应先独立验收；继续已有桌面对话还依赖该桌面实例和目标聊天可用。微信任务本身不要求先安装桌宠提醒 Hooks。

1. 先确认本机 Codex 或 Cursor CLI 能正常执行任务，已有模型服务、登录和所需网络配置可用。
2. 在小屋打开“微信接入”，点击“扫码连接”，用微信扫描并确认。扫码前不要求填写项目或客户端路径。
3. 在“微信设置 → 客户端”检查执行实例；默认使用本机 Codex。多实例可检测并添加到优先级，或自定义填写可执行文件绝对路径、Codex 配置目录和 profile。
4. 扫码账号自动授权。其他联系人须先发消息，再由电脑上的联系人授权入口放行；授权前的消息不会补执行。
5. 从微信发送 `/projects` 或 `/chats`，按编号选择项目或对话，再发一个简单问题，确认本机执行和微信回复都成功。

没有历史的新项目可以用 `/project 本机绝对路径` 指定。继续 Codex 桌面对话时，桌面客户端须保持运行并持有该聊天；配置目录必须对应同一个实例。该转发依赖内部 IPC，客户端升级后出现协议不匹配时，需要重新核对兼容性。

Cursor 通过已登录的 CLI，以 Ask 模式执行只读排查，不复用 Cursor 编辑器的已有聊天。只验证扫码成功不能证明执行客户端可用；所有执行实例停用时仍可连接微信，但不能执行任务。

微信接入通过本机主动长轮询接收消息、主动发送回复，不需要公网 IP、端口映射或额外部署中转服务器。电脑、应用及所用客户端需保持运行和联网，睡眠期间无法处理新消息。它提供微信消息通道，当前没有对外的额度 HTTP 查询接口或微信额度查询专用指令。

登录明确失效时重新扫码；临时断线可以等待自动重连或点击“重试连接”。微信配置通过系统安全存储加密保存，系统加密不可用时无法保存。完整命令及恢复行为见 [README 的微信说明](../README.md#微信远程排查)。

## 5. 邮箱接收

**前置条件：** 邮箱服务商允许第三方客户端接入，账号已开启 IMAP；企业邮箱如受管理策略限制，需先由邮箱管理员开通。

在邮箱服务商侧开启 IMAP，并取得客户端专用密码或授权码，再在小屋“邮箱接收”中填写配置：

| 配置项 | 飞书邮箱 | 自定义 IMAP |
| --- | --- | --- |
| 邮箱账号 | 完整邮箱地址 | 完整邮箱地址 |
| 服务器 | 自动使用 `imap.feishu.cn` | 填主机名，不带协议或路径 |
| 端口 | 自动使用 `993` | 填服务商提供的隐式 TLS 端口 |
| 密码 | 客户端专用密码 | 服务商要求的专用密码或授权码 |

点击“开始接收”；修改已有配置时按界面提示保存并接收。成功取得最近邮件后，打开一封确认正文可读。数量默认 20，可设为 1–100。

本功能直接连接 IMAP，不依赖飞书开放平台应用或 lark-cli。连接强制 TLS 并校验证书，不支持明文 IMAP、POP3 或 OAuth 登录。认证失败时先检查 IMAP 是否开启、授权码是否正确以及企业管理员限制；连接失败时检查地址、端口、网络和证书。账号及缓存保存在本机加密的 `mail.enc`，系统加密不可用时无法保存。

## 6. Archery 待我审核

**前置条件（按顺序完成）：**

1. 已有可访问的 Archery 服务及可登录账号；本地 MCP 面向 Archery 1.14 适配，其他版本需另行核对。桌宠不包含 Archery 服务端。
2. 安装我们维护并适配的 Archery MCP 及其 Python 运行环境，取得可执行程序绝对路径。它是独立项目，不随桌宠安装；步骤见 [Archery MCP 安装与启动说明](https://github.com/Cheny-1127/archery-mcp#安装与启动)。需提供 `work_order_pending_list`，审批时还需 `work_order_approve`。
3. 在桌宠读取的全局 `config.toml` 中注册 MCP 启动入口。账号配置沿用 MCP 已有配置，由 MCP 自行加载，无需在桌宠重复配置。
4. 核对工具启停策略与 Archery 服务端账号权限，再在桌宠中开启模块并刷新。仅需查看时，只需开放列表工具；审批还需要对应工具和账号审批权限。

缺少第 1–3 项时，开启模块不能完成接入；列表读取成功也不能证明审批权限可用。该模块由桌宠直接启动 MCP，无需先发起 Codex 模型对话。

Archery 页首次未配置时展开配置区，已有有效配置时默认收起；“在文件夹中显示”定位当前选定文件，不调用系统默认编辑器。连接状态以实际列表读取结果为准，开启自动刷新不代表已连接。

在小屋 **Archery → Archery MCP 配置** 中选择已有的 Codex 全局 `config.toml`，点击“保存并连接”。默认路径为 `$CODEX_HOME/config.toml`（未设置时是 `~/.codex/config.toml`），也可选择其他 Codex 配置目录下的文件。小屋仅将文件路径保存到本机 `archery-connection.json`，不会修改 Codex 配置或复制账号密码；待审核列表使用所选文件，重启保留。配置验证失败时保留旧来源；处理中禁止切换。可点击“使用默认路径”，再保存恢复默认来源。

桌宠读取所选全局配置中的 `mcp_servers.archery`，只支持本地 stdio 启动方式。`command` 必须是可执行程序的绝对路径；如果提供 `cwd`，也须为绝对路径。不会从项目局部配置或远程 MCP URL 读取此连接。

合并下面的配置示例到已有全局配置，不要重复声明同一个 TOML 表，也不要覆盖已有工具权限策略：

```toml
[mcp_servers.archery]
command = "/Users/yourname/.codex/mcp/archery/bin/archery-mcp"
enabled = true
```

将路径换成实际安装位置。已安装 MCP 会自行读取 Python 运行环境根目录的 `.env`，桌宠不会要求将其中的账号密码再写入 `config.toml`，也不会把 `.env` 密码复制到启动环境或本机设置。已有 `mcp_servers.archery.env`、`env_vars` 仍按原样传递，`env` 优先；从 Finder 启动不保证继承终端环境变量。

对于标准独立安装的 `bin/archery-mcp`（Windows 为 `Scripts/archery-mcp.exe`），桌宠读取同一运行环境 `.env` 的地址和账号，仅用于隔离账号缓存及检测配置变更；密码变化会使连接失效，且不会解除同账号的未知审批防重。自定义启动器仍可读取列表和审批。

全局工具白名单如有设置，须允许 `work_order_pending_list` 才能查看列表；还要允许 `work_order_approve` 才能逐笔审批。禁用列表不能包含相应工具，账号本身也须具备服务端权限。不需要审批时可只开放列表工具。

打开小屋“Archery”，连接成功后按钮显示“已连接”，配置自动收起；修改路径后显示“保存并连接”，连接失败可点击“重新连接”。点击整条工单摘要，在当前行下方展示 SQL 和执行结果，再次点击收起，切换工单只展开当前一条。详情首次通过 MCP 读取，按服务器、账号与工单编号隔离，加密缓存到本机 `archery-details.enc`，翻页、刷新或重启后复用。日常刷新只更新列表和状态，不重复读取完整 SQL；“重新加载详情”才重新获取 SQL 和执行结果。审核信息不展示或缓存，SQL 不进入全局快照。缓存最多保留 100 条、32 MiB，超出后淘汰最久未访问项；系统安全存储不可用时仅在本次运行中缓存，无法解密的原文件保留。大详情先提示大小，点击“加载完整详情”并确认后才完整加载。验收连接无需审批真实工单；无待办不一定是错误。审批时应用展示统一样式的应用内确认框，默认聚焦取消；直接按 Enter、Esc、切页或关闭窗口都会取消。明确确认后只请求审核通过，不连带执行 SQL。结果未知时到原工单核实，勿重复点击。

## 7. Sub2API 额度与消费排行

**前置条件：** 已有可访问的 [Sub2API 服务](https://github.com/Wei-Shaw/sub2api)，且对应管理接口可用；账号额度还依赖服务端已保存的上游额度或点数快照。Sub2API 的部署及上游账号接入需在该服务侧完成，桌宠安装不会代为创建这些服务或数据。

### 地址与凭据

当前界面没有服务地址配置入口，应用默认请求 `https://openai.minitvclub.com`。可以在本机 `.env` 修改地址，无需改代码。**先确认地址就是你有权访问、且准备为其提供管理 Key 的目标站点，再配置凭据。** 更换平台时，该平台必须支持下面列出的 Sub2API 管理接口；普通模型调用地址和 Key 不能代替它们。

在项目根目录执行以下命令。已有 `.env` 时直接编辑，不要覆盖：

```sh
# 仅在尚无 .env 时复制模板；重跑不会覆盖已有文件。
test -e .env || cp .env.example .env
chmod 600 .env
```

用本机编辑器打开 `.env`，填写实际站点和该站管理员后台取得的管理 Key：

```dotenv
WHALE_QUOTA_BASE_URL=https://your-sub2api.example.com
WHALE_QUOTA_API_KEY=replace-with-your-admin-key
```

Key 不加 `Bearer` 前缀。值含 `#` 或空格时，使用引号包住完整值；原生环境文件解析会移除外层引号。地址须为 HTTP(S) 站点根地址，可包含部署子路径，不能包含账号、密码、查询参数或片段，不要填写模型调用的 `/v1` 路径。账号额度、用户排行和 Key 今日消费统一使用此地址及凭据。

应用按项目所在目录读取 `.env`，不依赖终端当前目录；`npm start` 和 Finder 双击 `start.command` 均会读取。修改配置后须正常退出已有桌宠进程再启动，不支持运行中自动重载。读取失败或地址无效时启动会报错，不会偷偷切回默认站点。

同名进程环境变量优先于 `.env`，即使进程变量为空也覆盖文件中的同名值。`WHALE_QUOTA_BASE_URL` 未设置或为空时使用默认站点；`WHALE_QUOTA_API_KEY` 未设置或为空时，继续读取 `WHALE_QUOTA_TOKEN_FILE` 指定的文件，默认是项目根目录的 `token`，相对文件路径也按项目根目录解析。旧文件仍只保存 Key 原文。新管理 Key 非空时优先使用它，不再依赖旧文件。

`.env`、`.env.*`（模板 `.env.example` 除外）和 `token` 均被 Git 忽略；模板不含真实 Key。`.env` 是本机明文配置，不使用系统安全存储，应保持权限 `600`。不要将真实 Key 写入文档、截图或提交到仓库。额度模块不把 `.env` 中的管理 Key 注入全局进程环境，也不会将它传给执行任务的客户端子进程。

### 各区块需要的接口

| 区块 | 当前访问的 Sub2API 管理接口 |
| --- | --- |
| 上游账号额度 | `GET /api/v1/admin/accounts`、`GET /api/v1/admin/accounts/:id` |
| 用户消费排行及分组选择 | `GET /api/v1/admin/groups/all`、`GET /api/v1/admin/dashboard/user-breakdown` |
| Key 今日消费 | `GET /api/v1/admin/users`、`GET /api/v1/admin/users/:id/api-keys`、`POST /api/v1/admin/dashboard/api-keys-usage` |

打开“API 额度”，点击“立即刷新”。账号需在 Sub2API 中有可用的额度或点数快照，才会进入额度列表。该功能读取服务端已保存的数据，不主动刷新上游；“刷新时间”代表本机成功取数时间，不代表上游快照采集时间。

用户排行默认分组 ID 为 13，可切到实际分组或“全部分组”。Key 今日消费中选择的是 Sub2API 登录用户，不是上游订阅账号。各区块接口、权限和数据分别验收，一个区块成功不能证明其余区块可用。

如需在桌宠显示流量跟踪条，先完成账号额度同步，再在“流量跟踪配置”中选择有有效 7 天额度的账号。账号未同步、未选择或没有有效 7 天额度时，无法显示对应的剩余比例；只有点数余额也不足以显示 7 天额度条。

### v0.2.17 的权限边界

Sub2API v0.2.17 使用系统设置中的单个全局管理员 Key，没有可配置的受限管理 Key。本应用虽然只读取额度和统计，但该凭证本身有管理权限，不应把它发给仅需查看额度的人。

该版本的管理 Key 鉴权统一映射到 `GetFirstAdmin()` 返回的管理员，不能据此识别真实调用者；普通账号列表和详情 GET 也不在默认操作审计范围内。依据：[v0.2.17 鉴权源码](https://github.com/Wei-Shaw/sub2api/blob/v0.2.17/backend/internal/server/middleware/admin_auth.go)、[审计源码](https://github.com/Wei-Shaw/sub2api/blob/v0.2.17/backend/internal/server/middleware/audit_log.go)。其他版本须按对应版本核对，不能套用主分支能力。

读取失败时检查 `.env` 的目标站点、管理 Key、读取权限及已有进程变量是否覆盖配置；使用旧凭据文件时也检查其路径。再确认对应管理接口是否存在。刷新成功但无额度时，在 Sub2API 管理页面确认账号快照；HTTP 404 应核对版本和反向代理路径，不能直接判断为 Key 无效。

## 9. 启动环境、数据与迁移

以下是本应用实际读取的常用环境变量，不需要为未使用的功能设置。额度及工作报告的下列配置支持项目 `.env`，其余变量仍需由启动进程提供：

| 变量 | 用途 | 默认值或限制 |
| --- | --- | --- |
| `WHALE_QUOTA_BASE_URL` | Sub2API 站点地址 | `https://openai.minitvclub.com`；额度及两类消费统计共用 |
| `WHALE_QUOTA_API_KEY` | Sub2API 管理 Key | 非空时优先使用；为空时兼容旧凭据文件 |
| `WHALE_QUOTA_TOKEN_FILE` | 兼容旧 Sub2API 管理 Key 文件 | 项目根目录的 `token`；相对路径按项目根目录解析 |
| `WHALE_REPORT_OBSIDIAN_DIR` | 工作报告初始归档目录 | 已存在的绝对路径；首次读取后以页面保存的配置为准 |
| `WHALE_REPORT_JENKINS_URL` | Jenkins 地址 | 含必要的上下文路径，不含账号、查询或片段 |
| `WHALE_REPORT_JENKINS_USERNAME` | Jenkins 用户名 | 具有指定任务历史读取权限 |
| `WHALE_REPORT_JENKINS_TOKEN` | Jenkins API Token | 仅主进程读取，不写入报告数据 |
| `WHALE_CODEX_BIN` | Codex Hooks 检测与默认 Codex 执行程序 | 优先使用该变量；未提供可用文件时检查内置应用路径及 `PATH`，微信实例的显式路径优先于默认检测 |
| `CODEX_HOME` | Codex 配置目录，也用于全局 Archery MCP 配置查找 | `~/.codex`；微信自定义实例可单独指定目录 |
| `WHALE_DATA_DIR` | 桌宠数据与事件 socket 目录 | `~/Library/Application Support/deepsleep-whale-pet/` |
| `WHALE_CURSOR_HOME` | Cursor Hooks 配置目录 | `~/.cursor` |
| `WHALE_CURSOR_STATE_DB` | Cursor 聊天跳转使用的状态库路径 | `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb` |

终端变量只对继承该环境的进程生效。额度及工作报告配置可直接保存在项目 `.env`，不要求终端导出变量；已有同名进程变量优先。其他模块依赖自定义环境或代理时，仍从已配置的终端运行 `npm start`。改动配置后正常退出并重启，避免复用已启动的实例。

自定义 `WHALE_DATA_DIR` 时，桌宠与 Hooks 发送脚本必须使用同一目录，且 `events.sock` 的完整路径不能超过 100 字节。默认数据目录为兼容已有数据而保留 `-pet` 后缀，无需手动改名。

迁移或升级前正常退出应用，私下备份数据目录、`.env`、自行保存的 Key 文件及相关客户端配置。新电脑需重新确认站点授权、文件权限及本机路径。微信和邮箱文件使用系统安全存储加密，复制到另一台机器或另一个系统账号后不保证可解密，需准备重新扫码或填写邮箱授权码。不要通过删除整个数据目录来排查单个模块故障。

## 11. 常见问题

| 现象 | 先检查 |
| --- | --- |
| 模块入口和内容置灰 | 该模块右上角总开关，以及模块内的连接或来源开关 |
| 界面显示连接就绪，但没有实际结果 | 按功能表执行最小验收；手动动画、扫码成功、MCP 启动均不能代替完整收发或取数验收 |
| 终端启动正常，双击启动失败 | Node 路径及环境变量；自定义配置、代理是否只在终端中生效 |
| 微信能收到指令但不能执行 | 客户端是否启用且已登录、项目目录是否存在、桌面对话是否由所选实例持有 |
| Archery MCP 能用，桌宠却提示配置不完整 | 桌宠读取的全局配置位置，可在 Archery 页选择实际使用的全局 `config.toml`；核对 `env`／`env_vars` 是否提供账号，仅 MCP 的 `.env` 不够 |
| API 额度能用，某个统计区块失败 | 该区块需要的接口、站点版本、权限和选中的分组／用户 |
| 休眠或退出后不处理消息、收件或刷新 | 后台功能依赖本机进程运行与联网，无法在电脑关机期间提供服务 |
| 微信或邮箱提示无法解密 | 当前系统账号及安全存储状态，保留原文件再核实恢复方式 |

本文是配置说明，不代表已连接真实服务验收。自动化测试使用模拟数据，各站点凭据、网络和客户端版本仍需在实际使用环境按最小步骤确认。
